# Работа с Packaging-Filling-Hub из дома

Домашний компьютер подключается как отдельное рабочее место начальника. Рабочие компьютеры не открываются в интернет и не должны быть включены для домашнего доступа: каждая установка связывается с корпоративным Google самостоятельно.

## Установка дома

1. Убедитесь, что правила предприятия разрешают использовать корпоративный Google-аккаунт на домашнем компьютере.
2. Установите Node.js 20 LTS или новее.
3. Распакуйте установочный архив полностью.
4. Запустите `INSTALL-HOME-MANAGER.cmd`.
5. Настройте OAuth и Deployment ID по инструкции `README-INSTALLATION-RU.md`.
6. Выполните `VERIFY-INSTALLATION.cmd`.

Домашняя установка получает роль начальника и идентификатор `manager-home`. В аудите исправлений журнала будет указано «Домашний компьютер начальника».

Не включайте перенаправление портов на роутере, общий доступ Windows или публичный HTTP-адрес. Для этого варианта они не нужны.

## Какие данные можно исправлять дома

После подключения Google дома можно читать, добавлять, исправлять и аннулировать записи подключённых Google-журналов в пределах прав начальника. Контроль версий остаётся включённым: если запись уже изменена другим компьютером, программа не должна молча затереть изменение.

Персонал, настройки смен и табель в версии 0.6.1 ещё хранятся локально. Пока для них не создан общий источник Google, изменения этих разделов дома не появятся на рабочих компьютерах. Использовать их дома как общие данные пока нельзя.

## Как изменять саму программу дома

Исходный код редактируется в папке репозитория GitHub, а не в установленной папке `%LOCALAPPDATA%\Packaging-Filling-Hub`.

Обычный порядок:

1. получить свежие изменения из GitHub;
2. изменить исходники в Visual Studio Code;
3. выполнить `npm run check`;
4. зафиксировать и отправить изменения в GitHub;
5. собрать новый архив командой `npm run build:windows`;
6. повторно запустить нужный установщик на каждом компьютере.

Установщик обновляет программу, но сохраняет локальный `.env`. Автоматическое обновление рабочих компьютеров из GitHub пока не включено, чтобы непроверенное изменение не попало в производство само.

## Защита домашней установки

- используйте отдельную учётную запись Windows с паролем;
- не помещайте `.env` и OAuth JSON в GitHub, OneDrive или общую папку;
- после настройки удалите скачанный OAuth JSON;
- не очищайте данные браузера, если в программе остались неотправленные записи;
- при потере домашнего компьютера отзовите выданный Google OAuth-доступ.
