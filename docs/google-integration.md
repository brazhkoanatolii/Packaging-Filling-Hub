# Подключение Google Workspace

Google Sheets остаётся главным источником данных. Программа не переименовывает, не перемещает и не удаляет рабочие файлы. Она читает строки и вызывает уже установленную Apps Script-функцию для добавления или исправления данных.

## Текущее состояние

- рабочая таблица: `Data: Scale Verification Log (Журнал контроля весов)`;
- первый лист: `Контроль 50г`;
- защищённая функция `writeScaleRecord` уже установлена в Apps Script;
- в таблице есть постоянные идентификаторы, версии, защита от повторного запроса и контроль параллельных изменений;
- в репозитории подготовлены `listScaleRecords` и `writeScaleRecordV2` для чтения, исправления и аннулирования;
- подготовлен локальный шлюз, который хранит OAuth-данные вне браузера;
- запись в рабочую таблицу по умолчанию выключена.

## Почему нужен стандартный проект Google Cloud

В текущем Apps Script используется проект Google Cloud «по умолчанию». Внешний вызов через Apps Script API требует стандартный проект, причём OAuth-клиент шлюза и скрипт должны относиться к одному проекту. В этом проекте также требуется включить Apps Script API.

Переключение Apps Script с проекта по умолчанию на стандартный проект меняет его OAuth-настройки и требует повторного разрешения доступа. Поэтому это действие выполняется отдельно, после подтверждения начальника участка.

## Контракт шлюза

- `GET /api/scale-records` вызывает `listScaleRecords`;
- `POST /api/scale-records` вызывает `writeScaleRecordV2`;
- `GET /api/health` показывает только готовность настройки и не раскрывает секреты;
- сервер получает краткоживущий Google access token по refresh token;
- OAuth client secret и refresh token находятся только в локальном `.env`, который исключён из Git.

## Безопасность записи

Даже после подключения Google запись отдельно управляется параметром `GOOGLE_WRITES_ENABLED`. Сначала программа подключается в режиме чтения. Запись включается только на время контролируемой проверки:

1. создать одну тестовую запись;
2. прочитать её обратно из Google Sheets;
3. исправить эту же запись;
4. аннулировать её с причиной;
5. проверить строку, формулы, автора, версию и технические поля;
6. после успешной проверки оставить запись включённой.

Аннулирование не удаляет строку. Статус и причина сохраняются в существующей ячейке «Примечание» в виде служебной отметки, которую программа показывает отдельными полями.

## Офлайн-работа

Интерфейс и последние прочитанные данные сохраняются на компьютере. Новые операции остаются в локальной очереди и отправляются после восстановления сети. Перед перезаписью Google сравнивает версию; при чужом изменении программа создаёт конфликт и не затирает его молча.
