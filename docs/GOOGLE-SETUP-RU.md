# Что нужно сделать для подключения Google

Эта инструкция разделяет действия сотрудника и действия, которые можно выполнить автоматически. Пароли, OAuth client secret и refresh token нельзя отправлять в чат или сохранять в GitHub.

## Шаг 1. Корпоративный проект Google Cloud — действие сотрудника или администратора Google

Попросите администратора домена `kordula.eu`:

1. создать новый стандартный проект Google Cloud для программы «Packaging-Filling-Hub» или назначить существующий отдельный проект;
2. дать `anatolii.brazhko@kordula.eu` право подключить Apps Script к этому проекту и настроить внутренний OAuth-клиент;
3. включить в проекте **Google Apps Script API**;
4. сообщить только **номер проекта** (`Project number`). Это не пароль и не секрет.

Если у начальника участка уже есть эти права, всё можно выполнить в его учётной записи без обращения к администратору.

## Шаг 2. Подключение Apps Script — выполнит разработчик после отдельного подтверждения

Понадобится:

1. добавить файл `apps-script/scale-journal-api-v2.gs` в существующий проект Apps Script;
2. сохранить новую версию скрипта;
3. заменить проект Google Cloud «по умолчанию» на стандартный проект по его номеру;
4. повторно разрешить скрипту доступ к рабочей таблице;
5. развернуть скрипт как **API executable** и записать Deployment ID.

Смена проекта Google Cloud влияет на разрешения существующего скрипта, поэтому непосредственно перед этим действием требуется подтверждение.

## Шаг 3. OAuth — одно действие сотрудника в окне Google

В стандартном проекте создаётся внутренний OAuth-клиент. Начальник участка один раз входит под корпоративной учётной записью и подтверждает разрешения Google. Полученный refresh token сохраняется только на рабочем компьютере.

Не копируйте содержимое `client_secret.json`, client secret или refresh token в сообщения.

Для безопасной локальной настройки скачайте JSON настольного OAuth-клиента и выполните:

```powershell
npm run setup:google-oauth -- "C:\\путь\\к\\client_secret_....json"
```

Помощник откроет локальный обратный адрес, запросит только области `script.scriptapp` и `spreadsheets.currentonly`, а затем сохранит Client ID, Client secret и refresh token в исключённый из GitHub файл `.env`. После успешной настройки удалите скачанный JSON с секретом.

## Шаг 4. Локальная настройка — выполнит разработчик

После появления проекта и OAuth-клиента:

1. создаётся локальный `.env` по безопасному образцу `.env.example`;
2. заполняются Client ID, Client secret, refresh token и Deployment ID;
3. программа запускается через `npm run start:gateway`;
4. проверяется чтение таблицы при выключенной записи;
5. включается контролируемая запись и проводится полный тест;
6. на каждом рабочем компьютере и, если разрешено правилами предприятия, на домашнем компьютере начальника запускается соответствующий Windows-установщик и локальная проверка;
7. рабочая запись разрешается только после успешного результата `VERIFY-INSTALLATION.cmd` и проверки строки непосредственно в Google Sheets.

## Шаг 5. Второй компьютер и телефон

На первом этапе программа и шлюз устанавливаются локально на оба рабочих компьютера. Домашний компьютер начальника подключается таким же независимым способом, если предприятие разрешает использовать на нём корпоративный Google-аккаунт. На каждом разрешённом компьютере OAuth настраивается отдельно под тем же корпоративным аккаунтом, а роль и идентификатор устройства задаёт установщик.

Подключение телефонов потребует отдельного HTTPS-адреса в рабочей сети. Открывать локальный шлюз обычным HTTP на всю сеть нельзя: это ухудшит защиту секретов и не обеспечит надёжную PWA-работу.
